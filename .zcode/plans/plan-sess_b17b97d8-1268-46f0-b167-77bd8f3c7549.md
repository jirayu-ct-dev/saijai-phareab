# แผน Hardening ความปลอดภัยทั้งระบบ + LINE Login (4 ระยะ)

## สรุปผลตรวจสอบที่พบ (จากการ audit โค้ดจริงทั้งระบบ)

**จุดที่แน่นอยู่แล้ว (ไม่ต้องแก้):** LINE ID token ถูก verify ฝั่ง server กับ `api.line.me` พร้อมตรวจ `aud`, webhook LINE ใช้ HMAC-SHA256 + `timingSafeEqual`, `/api/me/**` ทั้ง 21 handler ไม่มี IDOR, `/api/admin/**` ทั้ง 93 handler มี `requireRole` ครบ, กัน open-redirect, ไม่มี secret รั่วไปฝั่ง client, ไม่มี mass assignment, ธุรกรรมเงินใช้ state machine + `$transaction` + optimistic lock

## ระยะที่ 1 — Critical

**1.1 ปิดช่องโหว่ privilege escalation** (`app/utils/auth.ts`)
- เพิ่ม `input: false` ให้ `role`, `isActive`, `deletedAt`, `deletedById` และ `normalizedPhoneNumber` (derived field — ต้องผ่าน `me/profile.put` ซึ่ง derive ให้เท่านั้น)
- ตรวจว่า `server/api/admin/users/**` (ใช้ Prisma ตรง + `ALLOWED_ROLES`) และ `me/profile.put.ts` ยังทำงานได้ปกติ
- ปรับ client sign-up ใน `app/composables/useUser.ts:74-79` ถ้าการส่ง `role: "USER"` ไปแล้ว error หลังปิด input
- ทดสอบยืนยันใน dev: `curl POST /api/auth/update-user` กับ body `{"role":"ADMIN"}` ต้องไม่เปลี่ยน role

**1.2 Upgrade better-auth 1.5.3 → >= 1.6.22** (ล่าสุด stable)
- แก้ `package.json`, `pnpm install` (อัปเดต `pnpm-lock.yaml` ตามกติกา committed lockfile)
- อ่าน CHANGELOG ระหว่าง 1.5.3→1.6.x เรื่อง prisma adapter, session, socialProviders.line, additionalFields
- รัน `pnpm test` + typecheck + build และทดสอบ login ใน dev

**1.3 Security headers** — เพิ่มผ่าน `routeRules` ใน `nuxt.config.ts` (ไม่เพิ่ม dependency ใหม่)
- `Strict-Transport-Security: max-age=15552000`, `X-Content-Type-Options: nosniff`, `Referrer-Policy: strict-origin-when-cross-origin`, `Permissions-Policy: camera=(), microphone=(), geolocation=()`
- CSP ที่รองรับ LIFF: `default-src 'self'`, `img-src 'self' data: blob: https://res.cloudinary.com`, `connect-src 'self' https://api.line.me`, `style-src 'self' 'unsafe-inline'`, `frame-ancestors https://*.line.me`, `script-src` ตามวิธีโหลด LIFF SDK (npm bundle หรือ CDN — ตรวจตอน implement) — **ไม่ใช้ X-Frame-Options** เพราะ LIFF รันใน iframe ของ LINE
- ทดสอบ LIFF จริง (LINE dev tools / มือถือ) ว่าไม่พังก่อน finalize CSP

**1.4 Timing-safe CRON_SECRET** — สร้าง util `timingSafeCompare` (ถอดแบบจาก `line-messaging.ts:250-262`) แล้วใช้ใน `package-expiry.post.ts:8` พร้อม length check + Vitest

## ระยะที่ 2 — LINE Login hardening

**2.1 Webhook replay protection** (`server/api/line/webhook.post.ts`)
- Dedupe `webhookEventId` ด้วย in-memory Map + TTL (เหมาะกับ deployment single-instance, ไม่ต้องแต่ schema/migration)
- Log-skip เมื่อ `deliveryContext.isRedelivery` เป็น true
- เพิ่ม unit test dedupe logic

**2.2 Session policy ให้ชัดเจน** (`app/utils/auth.ts`) — `session: { expiresIn: 7 วัน, updateAge: 1 วัน }` (ค่าเดิมของ lib แต่ประกาศเป็นนโยบายของระบบ + เผื่อ config rateLimit ชัดเจนถ้าเวอร์ชันใหม่รองรับ)

**2.3 เก็บ LIFF token ออกจาก URL hash** — ใน `liff-init.client.ts` เมื่อตรวจพบ `access_token`/`id_token` ใน hash ให้ `history.replaceState` ล้างออก

**2.4 Rate limit จุดที่ขาด**
- Generalize `customerClaimRateLimit.ts` เป็น in-memory limiter factory แบบเบา แล้วใช้ที่: `me/packages/interest.post.ts` (ต่อ user, กัน spam LINE push) และ `me/avatar.post.ts` (กัน spam upload)

## ระยะที่ 3 — API hardening

- **3.1** เพิ่ม mime allowlist (jpeg/png/webp) + size cap 5MB ใน 4 upload endpoints ตาม pattern `admin/payments/upload.post.ts:17-23` (extract helper ใน `server/utils/cloudinary.ts`)
- **3.2** Clamp ช่วงวันที่ใน `parseDateRange` (`csv.ts`) เช่น max 366 วัน และ cap จำนวน iteration ใน chart endpoints
- **3.3** `me/payment/index.get.ts` — ตัด raw metadata (เหลือ VAT fields อย่างเดียว เหมือน `[id].get.ts:204-214`); `me/payment/[id].get.ts` — ไม่ส่ง email พนักงานกลับให้ลูกค้า
- **3.4** `document.get.ts` — `encodeURIComponent(id)` + error 500 ตอบ message ไทยกลางๆ (log URL/stack ฝั่ง server เท่านั้น)
- **3.5** Last-admin guard ใน `admin/users/[id].put.ts` (ยืม pattern `me/account.delete.ts:14-24`) + ทดสอบ
- **3.6** ย้าย `me/addresses/*.ts` ไปใช้ `readValidatedBody` (ให้ตอบ 422 ไม่ใช่ 500) และเปลี่ยน `me/packages/interest.post.ts` เป็น Zod schema
- **3.7** CSV formula-injection neutralization ใน `csv.ts` (prefix `'` กับค่าที่ขึ้นต้น `=`/`+`/`-`/`@`) + unit test
- **3.8** Escape displayName ใน email HTML (`email.ts`)
- **3.9** เพิ่ม hard cap (เช่น take: 500 รายการล่าสุด) ให้ list endpoints ที่ unbounded — ตรวจ caller ฝั่ง frontend ทีละจุดก่อนเปลี่ยน โดยเน้น `me/payment/index`, `me/membership/index` ก่อน (ฝั่งลูกค้า) และ admin lists ใส่ cap แบบไม่เปลี่ยน response shape

## ระยะที่ 4 — Infrastructure & เอกสาร

- **4.1** Dockerfile: รัน non-root (`USER node`) + ทดสอบว่า Puppeteer/@sparticuz/chromium ยัง render ได้
- **4.2** Sync `.env.example` กับ env ที่โค้ดใช้จริง (`LINE_TEST_USER_ID`, `LINE_DATA_MESSAGING_API` ไม่ถูกใช้ — รายงานให้ผู้ใช้ลบจาก `.env` เอง, ไม่แตะไฟล์ `.env` จริง) 
- **4.3** เขียน section "ความปลอดภัย" สั้นๆ ใน README.md: headers ที่ตั้ง, rate limiting, การตัดสินใจไม่บังคับ email verification, accepted risks (plaintext phone/LINE ID, session token plaintext ถ้า better-auth เวอร์ชันใหม่ยังไม่รองรับ hashing — จะตรวจหลัง upgrade แล้วทำถ้ามี built-in)
- **4.4** ลด PII ใน log: ตัด `lineUserId` ออกจาก error log ใน `notify.ts:136`, `notifyExpiring.ts:156`

## การตรวจสอบ (ทุกระยะและรอบสุดท้าย)

1. `pnpm test` — เพิ่ม Vitest สำหรับ: timing-safe compare, webhook dedupe, date-range clamp, CSV sanitize (test ปัจจุบันเป็น Node-env unit tests ตามข้อจำกัดของ repo)
2. `pnpm exec nuxi typecheck` — แยก baseline errors เดิมออกจากที่งานนี้ก่อ
3. `pnpm run build`
4. ทดสอบ runtime ด้วย `docker compose -f docker-compose.local.yml up --build -d`: login LINE ใน LIFF browser, ตรวจ headers ด้วย `curl -I`, ยิง `POST /api/auth/update-user {"role":"ADMIN"}` ยืนยันว่าเป็น 403/ignore, ทดสอบ CSP ไม่หัก LIFF
5. Commit แยกตามระยะ/หัวข้อ บน branch dev

## ขอบเขตที่ตั้งใจไม่ทำ
- ไม่เปลี่ยน prisma schema / ไม่มี migration ใหม่ (dedupe ใช้ in-memory)
- ไม่เพิ่ม production dependency ใหม่ (headers ทำเอง, limiter ทำเอง)
- ไม่บังคับ email verification, ไม่เปลี่ยน flow claim-customer
